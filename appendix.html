Cadence/Methodology
Under the hood

The technical method.

RevOps only holds up if the math does. Here's the logic Cadence uses to size markets, forecast pipeline, score risk, and build simulators — the same primitives behind every case study.

01 — Market sizing

Account-level TAM & penetration

Every account gets a fitted addressable value, then a penetration ratio. That ratio is what drives the 12-box: high value + low penetration is where the incremental dollar hides.

-- Account TAM roll-up with penetration SELECT a.territory, a.segment, SUM(a.fitted_tam) AS tam, SUM(a.actual_revenue) AS revenue, ROUND(SUM(a.actual_revenue) / NULLIF(SUM(a.fitted_tam),0), 3) AS penetration FROM accounts a WHERE a.fit_flag = TRUE GROUP BY a.territory, a.segment ORDER BY tam DESC;
02 — Forecast

Scenario-weighted revenue

The forecast is never a single line. Expected revenue is stage-weighted pipeline plus retained base, run across conservative / base / stretch scenarios so leadership sees the range, not a false point estimate.

# Scenario-weighted expected revenue expected = base_retained + sum( stage_amount[s] * win_rate[s] * scenario_factor for s in pipeline_stages ) # scenario_factor: conservative 0.85 | base 1.00 | stretch 1.15 coverage_needed = target / blended_win_rate
03 — Risk

Adoption risk tiering

Renewal risk is a signal, not a surprise. Accounts are tiered on usage trend, engagement depth, and renewal proximity so intervention happens while it still matters.

  • At risk — declining adoption or renewal inside 90 days with weak engagement.
  • Watch — flat usage, single-threaded, or below the healthy-usage threshold.
  • Stable — consistent multi-user adoption above threshold with expansion signal.
04 — Data integrity

Checks before conclusions

No model ships without validation. Standard gates on every engagement:

  • Duplicate account detection and deterministic dedup keys.
  • Missing-value imputation for enrollment / firmographic fields.
  • Outlier capping on TAM so a few giants don't distort territory rollups.
  • Penetration bounded to a sane 0–100% range.
  • Cross-validation against known high and low performers.
05 — Simulators

From model to lever
